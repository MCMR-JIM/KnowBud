# Sprout：面向学龄儿童的本地伴学桌面应用

## 摘要

Sprout 是一个完全本地化的儿童 AI 伴学系统。与直接让大模型"扮演老师"的常规方案不同，Sprout 将教学流程的控制权交还给一个确定性的**有限状态机决策引擎**，大语言模型仅作为可替换的内容生成技能（出题、评估、分类）。系统内置知识图谱自动策展管线，能够从家长上传的教材文档中自动提取知识点、定位图谱位置、生成教学素材。前端为 React + TypeScript 单页应用，提供分离的儿童学习端与家长管理看板，后端为 Python FastAPI HTTP 服务，语音栈（ASR/TTS）完全本地化，断网可用。

## 1. 项目背景

当前多数 AI 教育产品的核心问题在于将教学流程完全交由大模型编排——模型输出不可控、节奏不稳定、存在幻觉风险，且严重依赖网络。Sprout 的设计回应了三个关键约束：

1. **教学流程必须确定化**：LLM 不参与流程控制，只负责内容生成
2. **家长必须能介入**：上传教材、管理知识结构、推送复习任务
3. **无网也必须可用**：本地 ASR/TTS/LLM 全链路离线运行

关键设计决策：
- **通信协议**：纯 RESTful HTTP，流式语音通过 `StreamingResponse` 返回 `audio/mpeg` 字节流，中断通过 `POST /interrupt/{stream_id}` 设置 `threading.Event` 信号。不涉及 WebSocket。
- **配置热加载**：每次文档摄入前从 `llm_settings.json` 重新读取 LLM 配置，非缓存单例。
- **摄入异步化**：后台 `threading.Thread(daemon=True)` 执行文档摄入，前端通过轮询 `/ingestion-status` 获取实时进度。

## 3. 核心子系统

### 3.1 FSM 决策引擎

决策引擎是 Sprout 区别于 LLM-native 教育产品的核心。它是一个具有 6 条优先级规则的有限状态机：

```python
class DecisionEngine:
    def evaluate(self, *, state: LearningState, curriculum: CurriculumConfig,
                 intent: UserIntent, user_answer_text: str | None = None) -> DecisionResult:
        # 规则 0：复习队列抢占 (最高优先级)
        if state.review_queue and state.current_phase in {
            LearningPhase.NOT_STARTED, LearningPhase.MASTERED
        }:
            return self._handle_review_priority(state)

        # 规则 1：开始学习 — 分配新知识点
        if state.current_phase == LearningPhase.NOT_STARTED:
            return self._start_learning(curriculum)

        # 规则 2：学习完成 → 进入练习
        if state.current_phase == LearningPhase.LEARNING and intent == UserIntent.MARK_LEARNING_DONE:
            return self._start_practice()

        # 规则 3：练习阶段答案评估
        if state.current_phase == LearningPhase.PRACTICING and intent == UserIntent.SUBMIT_ANSWER:
            return self._evaluate_practice_answer(state, user_answer_text)

        # 规则 4：连续错误阈值 → 触发复习
        if state.consecutive_wrong >= self.fail_threshold:
            return self._trigger_review(state)

        # 规则 5：连续正确阈值 → 标记已掌握
        if state.consecutive_correct >= self.master_streak:
            return self._mark_mastered(state)

        return DecisionResult(action=NoopAction(), state_delta=StateDelta())
```

输出为 `DecisionResult`（ActionCommand + StateDelta + trace），而非 LLM 自由文本。这保证了每次交互的可预测性。

### 3.2 知识图谱系统

#### 3.2.1 图谱提案生命周期

```
PROPOSED ──→ VALIDATED ──→ SHADOW ──→ ACTIVE
    │                         │
    └──────── REJECTED ←──────┘ (连续错误回滚)
```

- **PROPOSED**：LLM 从资源或提问中生成的新知识点提案
- **VALIDATED**：通过初步去重和合理性校验
- **SHADOW**：以影子节点形式存在，收集学习表现数据
- **ACTIVE**：观察期内表现达标，正式激活为知识节点
- **REJECTED**：重复、不合格或学习表现差，驳回

#### 3.2.2 影子节点观察与决策

```python
# 影子节点推广条件 (从环境变量加载)
SHADOW_PROMOTE_DEPTH = 2            # 掌握深度 >= 2
SHADOW_PROMOTE_SUCCESS_COUNT = 2    # 累计正确 >= 2 次
SHADOW_PROMOTE_STABILITY = 1        # 稳定性 >= 1
SHADOW_ACTIVATE_OBSERVATION_TURNS = 2  # 观察回合数 >= 2

# 回滚条件
SHADOW_ROLLBACK_WRONG_STREAK = 2    # 连续错误 >= 2 次
```

#### 3.2.3 图谱检索代理 (GraphSearchAgent)

在多轮工具调用中搜索已有知识图谱以匹配新内容：

```
用户问题 "现在进行时是什么？"
  → Round 1: search_knowledge_graph("现在进行时") → 找到 "英语时态" 节点
  → Round 2: get_topic_details("english_tenses") → 获取子节点列表
  → Round 3: search_knowledge_graph("进行时") → 找到 "现在进行时" (弱匹配)
  → Decision: link (关联已有节点) 或 propose (创建新节点)
```

最多 5 轮工具调用，每轮 LLM 决定调用哪个工具或输出最终决策。

### 3.3 文档摄入管线

这是 Sprout 的技术壁垒——将家长上传的教材自动转化为结构化知识图谱。

#### 3.3.1 双管线架构

```
上传文档 (PDF/DOCX/PPTX/图像)
    │
    ├── 传统管线 (legacy pipeline)
    │   文档解析 → 逐文本块 LLM 分类 → 图谱搜索 → 链接/提案
    │   适用：无学科上下文、探索性上传
    │
    └── 结构化管线 (new pipeline, enable_new_pipeline=True)
        ① 文档扫描 (LLM)
           识别：doc_type (textbook/workbook)、blocks (lesson/word_list/exercise/appendix)
        ② 主题块提取 (LLM, 并行)
           每个 topic_area block → 提取知识点列表 [{title, desc}]
        ③ 树形组织 (LLM)
           确定知识点间的层级与前置关系
        ④ 图谱定位 (GraphLocator, LLM)
           逐个知识点在已有图谱中找到精确插入位置：
           exists / insert_as_child / insert_before / insert_after / create_relay_parent
        ⑤ 候选图谱生成
           构建 CandidateGraph (nodes + relays + edges + merges)
        ⑥ 候选审核 (CandidateReview)
           命名校验：冗余名称、练习题标题、近似重复
           逻辑校验：错误父节点、前置反转、孤立节点、跨学科边
        ⑦ 编译入库
           将通过审核的 CompilableNode 写入图谱，更新 ResourceRecord
```

#### 3.3.2 文档结构分析

`DocumentAnalyzer` 通过两级分析识别文档中的不同区域类型：

- **确定性规则**：基于 marker 关键词（"Lesson"/"Unit"/"单词"/"练习"/"附录"）和大写标题模式
- **LLM 模糊阅读**：对规则无法确定的段落，发送 LLM 进行语义判断

```python
# 区域类型
topic_area     # 教学核心区 → 进入主题提取
word_list      # 单词表 → 跳过 (仅词汇，无知识结构)
exercise_only  # 纯练习 → 跳过 (但尝试关键词绑定到最近知识点)
appendix       # 附录/索引 → 跳过
```

#### 3.3.3 摄入进度追踪

整个管线提供四阶段实时进度反馈：

| 阶段 | pipeline_stage | 前端显示 |
|------|---------------|---------|
| 文档解析 | `parsing` | 文档解析中 |
| 知识提取 | `candidate_extraction` | 候选节点提取中 |
| 图谱审核 | `review` | 候选结构已生成 |
| 编译入库 | `compiling` | 编译入图中 |
| 完成 | `completed` | 已完成 |
| 失败 | `failed` | 解析失败 |

通过 `GET /v1/resource/{id}/ingestion-status` 返回 `stage`、`pipeline_stage`、`candidate_node_count`、`segment_count` 等字段。

#### 3.3.4 多格式解析

- **PDF**：PyMuPDF (fitz) 提取文本；图像型/扫描件走 MinerU (基于 torch + transformers 的 OCR 管线)
- **DOCX**：python-docx 提取段落文本
- **PPTX**：python-pptx 提取幻灯片文本
- **MinerU Worker**：`scripts/mineru_worker.py` 子进程封装，输出统一的 Markdown + content_list + images_dir

#### 3.4.1 三模式部署

| 模式 | ASR | TTS | 说明 |

#### 3.4.2 流式合成与中断

```python
@app.get("/v1/session/output/audio/stream/{stream_id}")
async def stream_reply_audio(stream_id: str):
    """流式返回 TTS 音频 chunk，支持前端边收边播"""
    job = runtime.get_stream_job(stream_id)
    async def _iterator() -> AsyncIterator[bytes]:
        async for chunk in backend.synthesize_reply_audio_stream(
            job.text, stop_signal=job.stop_signal
        ):
            if job.stop_signal.is_set():
                break
            yield chunk
        runtime.consume_stream_job(stream_id)
    return StreamingResponse(_iterator(), media_type="audio/mpeg")

@app.post("/v1/session/output/audio/interrupt/{stream_id}")
def interrupt_stream(stream_id: str):
    """设置停止信号，中断正在播放的语音流"""
    interrupted = runtime.interrupt_stream(stream_id)
    return {"stream_id": stream_id, "interrupted": interrupted}
```

### 3.5 LLM 集成

#### 3.5.1 LLM 网关抽象层

为消除各服务中分散的 `client.chat.completions.create()` 调用，统一为三个函数：

```python
# src/services/llm_gateway.py

def call_llm(backend, *, messages, tools=None, tool_choice=None,
             temperature=0.3, timeout=60.0, extra_body=None):
    """通用 LLM 调用，返回完整 ChatCompletion 对象"""

def call_llm_json(backend, *, messages, temperature=0.3, timeout=60.0):
    """强制 JSON 输出，自动剥离 ```json 围栏，返回 dict/list"""

def call_llm_text(backend, *, messages, temperature=0.3, timeout=60.0):
    """纯文本输出，返回 str"""
```

网关自动处理 DeepSeek 的特殊 `extra_body={"thinking": {"type": "disabled"}}` 配置（避免推理模式导致极端延迟），以及 `__future__` annotations 与 FastAPI Request 注入的兼容性。

#### 3.5.2 本地 LLM 推理

```python
# src/services/local_llm_server.py
# 基于 HuggingFace Transformers + Torch，异步子进程启动，避免阻塞 FastAPI

class LocalLLMServer:
    def start(self):
        self._process = subprocess.Popen(
            [sys.executable, "-m", "src.services.local_llm_server"],
            env={**os.environ, "MODEL_PATH": self.model_path},
        )
```

通过 `llm_settings.json` 配置本地模型路径，支持 Gemma 3 等模型。启动时自动检测 GPU 可用性，CPU 模式下使用 int8 量化降低内存占用。

### 3.6 探索窗口机制

当掌握度引擎判定一个知识点达到**真正掌握**状态时，系统为儿童打开一个可配置时长（默认 5 分钟）的探索窗口。在此期间：
- 儿童的提问**不被限制**在当前知识点范围内
- 非计划内的问题**自动生成知识图谱提案**（而非被忽略）
- 窗口关闭后进入冷却期（默认 8 分钟），防止频繁切换

```python
# 环境变量控制
EXPLORE_WINDOW_MINUTES = 5           # 探索时长
EXPLORE_WINDOW_COOLDOWN_MINUTES = 8  # 冷却时长
```
